ApplyReady — app map

Paste an announcement → a ranked, deadline-paced checklist → a daily email listing what's left, until you submit.

The main pieces

  • Next.js app (pages + API routes) on Vercel — everything you see and every endpoint.
  • LLM gateway (Oxion, River as automatic fallback) — turns text into JSON, checked by a Zod schema.
  • Planner (lib/plan.ts) — plain code that sets best-by dates from the deadline.
  • Supabase — two tables (applications, checklist items) and the user accounts behind magic links.
  • Email — your own SMTP mailbox (Resend fallback); Vercel Cron triggers the daily send.

One action, end to end: scanning an announcement

Route through the code (reference route)

  1. Input: components/landing/PasteBox.tsx → scan(). Detects a link vs. text, calls /api/fetch-page for links, drives the progress stages, then posts the text to /api/scan and navigates to the new dashboard.
  2. Logic: app/api/scan/route.ts → POST. Calls extractAnnouncement() in lib/ai/extract.ts (schema check, one retry, provider failover), rejects non-applications, runs buildPlan() in lib/plan.ts (deadline passed / tight / no deadline), and saves with createApplication() in lib/db.ts.
  3. Result: app/a/[id]/page.tsx loads the row and renders components/dashboard/Dashboard.tsx; ticking calls PATCH /api/items/[itemId] from components/dashboard/Checklist.tsx. The same data feeds reminderEmail() in lib/email/templates.ts.

To change this, start here

What the AI extracts or how it ranks importance

lib/ai/prompt.ts (buildSystemPrompt) for instructions; lib/ai/schema.ts (ExtractionSchema) for the shape. Run npx tsx --env-file=.env.local scripts/try-extract.mts on the fixtures afterwards.

How best-by dates are spaced

lib/plan.ts → buildPlan(). Add a case to tests/plan.test.ts first, then npm test.

Reminder email wording or timing

Wording: lib/email/templates.ts → reminderEmail(). Timing: vercel.json (cron schedule) and the filters in applicationsDueReminder() in lib/db.ts.

Which mail service sends

lib/email/send.ts → sendEmail(): SMTP when SMTP_HOST is set, Resend otherwise.

Dashboard layout

components/dashboard/Dashboard.tsx; guidanceGoesLeft() decides which column gets Writing guidance. Colours live in app/globals.css.

A practice to reuse

Run real inputs through the core early, and turn each surprise into a test.

The spec planned to schedule tasks end to end back from the deadline. Running three realistic fixtures in slice 1 (scripts/try-extract.mts) showed an 11-task scholarship with 42 days left flagged "tight", because real tasks overlap. The fix in buildPlan() came with a test that pins the behaviour: tests/plan.test.ts → "does not call a long plan tight just because tasks add up past the deadline". The same habit caught a second gap when the primary AI gateway went down mid-build and led to automatic failover. On any project: feed the riskiest piece real data before building around it, and write down what you learn as a check that runs every time.

Run it again

npm install → copy .env.example to .env.local and fill it in → npm run dev → http://localhost:3000. Tests: npm test.
