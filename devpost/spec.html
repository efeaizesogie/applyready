How ApplyReady is built

One Next.js app on Vercel, three outside services, one daily timer. Step through the journey to see which pieces light up.

Architecture · step through the journey

In plain language

The AI proposes, the code decides dates. The model (via Oxion) reads the announcement and returns JSON: what's required, how important it is, and roughly how many days each item takes. Zod checks the shape (one retry if it's wrong). Then lib/plan.ts counts backward from the deadline to set each best-by date, because models are unreliable at calendar maths.

"Daily" is just one timer. Vercel Cron calls /api/cron/daily once a day. That route asks the database who's in progress, confirmed, and not yet reminded today, builds each email from the unticked items, and sends it through Resend. The demo button reuses the same builder for one application.

The link is the key. Each dashboard lives at an unguessable /a/[id], so email links work on any device. The magic link (Supabase) ties applications to your email and unlocks My applications.

Where it breaks, and what you see

Link blocked / JS-only page

"We couldn't read that link. Paste the announcement text instead." The text box is focused.

AI returns bad JSON

One retry with the validation error. Then "We couldn't read that announcement — try pasting the text." Nothing is saved.

AI is slow

Progress keeps moving; at 45s, abort with a retry button.

Email not delivered

Show the real error, never a fake "sent". For the demo, use your Resend account email.

Cron misses a day

last_reminder_at < today lets the next run catch up. No double sends.
